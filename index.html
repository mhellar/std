Getting Strudel to Talk to TouchDesigner

via VB-Cable + Optional OSC

What You Need:

  • Strudel (browser or standalone)
  • SuperCollider (if you want more control)
  • VB-Cable (virtual audio cable - free download)
  • TouchDesigner

The Basic Chain:

Strudel → VB-Cable → TouchDesigner → Projection

Step 1: Install VB-Cable

Download VB-Cable from vb-audio.com (it's free, the site looks sketchy but it's legit). Install it. Restart your computer because audio drivers.

Step 2: Route Strudel Audio to VB-Cable

In Strudel (or your browser), set your audio output to "VB-Cable Input". This sends all your Strudel sound into the virtual cable instead of your speakers.

If you're using SuperCollider with Strudel, you set SuperCollider's audio output to VB-Cable. Same idea.

Step 3: Set TouchDesigner Audio Input

In TouchDesigner, add an Audio Device In CHOP. Set its device to "VB-Cable Output" (yes, output—you're receiving what VB-Cable is outputting). Now TD is listening to whatever Strudel is sending.

Step 4: Analyze the Audio

Use CHOPs to analyze the incoming audio:

  • Audio Spectrum CHOP for frequency analysis
  • Audio Band EQ CHOP to isolate frequency ranges (bass, mids, highs)
  • Math CHOPs to scale/smooth the values

Heres an audio reactive TouchDesigner project for you to play with!

Step 5: Map to Visuals

Take those CHOP values and drive whatever—geometry transforms, shader parameters, particle systems, whatever you're projecting. The audio becomes control data for your visuals.

Important:

You won't hear your audio anymore because it's going to VB-Cable instead of your speakers. Either:

  • Use VB-Cable's "listen to this device" option in Windows sound settings, or
  • Get a second virtual cable and route things more complexly, or
  • Just deal with not hearing it during setup (you'll hear it in performance through the venue system)

The Feedback Loop:

Strudel pattern changes → audio changes → TD receives different frequencies → visuals respond → projection updates on cardboard

immediate responsive chain, everything's live

Troubleshooting:

  • If TD isn't receiving audio, check the Audio Device In CHOP device name exactly matches VB-Cable
  • Sample rate mismatches can cause issues—make sure everything's at 44.1kHz or 48kHz consistently
  • VB-Cable sometimes needs a restart to show up properly

OPTIONAL: OSC for More Control

if you want direct parameter control instead of just audio analysis, use OSC (Open Sound Control). this gives you way more precision.

OSC Chain:

Strudel → OSC messages → TouchDesigner

In Strudel:

You can send OSC from Strudel patterns using .osc() or .ccn() functions:

note("c3 e3 g3").osc("/pattern1")
s("bd sd").ccn(20, saw.range(0,127)).osc()

Strudel sends OSC to localhost:57120 by default (SuperCollider) but you can redirect it.

In SuperCollider:

If you're using SC with Strudel, you can forward OSC messages to TD:

~tdAddr = NetAddr("127.0.0.1", 7000); // TD's OSC port

OSCdef(\forwardToTD, { |msg, time, addr, port|
    ~tdAddr.sendMsg("/strudel", msg[1], msg[2], msg[3]);
}, '/pattern1');

In TouchDesigner:

Add an OSC In DAT. Set it to listen on port 7000 (or whatever port you chose).

The OSC In DAT outputs messages as table data. Use a DAT to CHOP to convert OSC values into usable channels for your visuals.

Why OSC?

  • Send specific parameter values instead of just audio analysis
  • Control multiple visual parameters independently
  • Sync timing events precisely
  • Send triggers for scene changes, shader switches, whatever

Example Workflow:

  • Strudel pattern sends OSC message with note value
  • TD receives it via OSC In DAT
  • DAT to CHOP converts it to a channel
  • Math CHOP scales it to useful range (like 0-1 for shader input)
  • Shader or geometry uses that value directly

You can run audio (VB-Cable) AND OSC simultaneously—audio for reactive stuff, OSC for precise control.

OSC Troubleshooting:

  • Make sure ports match between sender and receiver
  • Firewall might block localhost OSC (usually not but check if nothing's coming through)
  • OSC In DAT has a "Active" toggle—make sure it's on
  • Check the OSC In DAT table to see if messages are arriving

Combined Approach:

Some people run both—VB-Cable for audio-reactive visuals (responds to overall sound energy, frequencies) and OSC for precise parameter control (specific note values, timing triggers, pattern data). Gives you reactive AND controlled simultaneously.
